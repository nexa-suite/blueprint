# Mobile Requirements Derivation Sources

Derivation follows `Research evidence → Segment → Synthetic Persona → As-Is
Task / Journey → Product Goal / Outcome → Capability → BC authority → Mobile
Story / AC → Design → Technical enabler → Implementation → Technical
Verification → Product Acceptance → System Acceptance`. Product Generation and
academic Sprint assignment are planning dimensions, not evidence of delivery.

| Notifications/push | Mobile User; both apps | CAP-14; BC-10 plus technical contracts | provider/solution decision remains open | solution validation open |

Historical Web/academic wording is source evidence, not Mobile research.
Needfinding does not prove implementation, Product Acceptance or production
readiness. Open questions cover offline boundaries, push provider,
camera/GS1/QR, location/privacy, temperature/evidence, accessibility and
recovery.
