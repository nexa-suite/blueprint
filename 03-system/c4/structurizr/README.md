# C4 Structurizr

Reviewed tool version: `structurizr/structurizr:2026.06.28`.

`workspace.dsl` is the canonical semantic C4 source. `workspace.json`, if generated by Structurizr through layout editing, is a generated/compiled representation including layout and is not hand-written.

The source uses modular `!include` composition. V1 views exclude future people, future containers and future external systems. Runway views include planned Mobile, Driver, V2, identity-provider and IoT/telemetry elements with explicit future tags. Selective component views are included for the API, Platform and Portal; deployment views are not created.

The V1 system-context question is **who uses Nexa and which external systems does it depend on?** The V1 container question is **which major runnable applications and data stores make up Nexa?** Local Docker services are not added merely because Compose declares them; see the [canonical C4 rationale](../README.md) and [runtime evidence](../../../06-delivery/as-is/compose-runtime-architecture-evidence.md).

Expected views:

- `Nexa-SystemContext-V1`
- `Nexa-Containers-V1`
- `Nexa-SystemContext-Runway`
- `Nexa-Containers-Runway`
- `Nexa-API-Overall-ASIS`
- `Nexa-API-IdentityTenantCustomer-TARGET`
- `Nexa-API-CommercialInventory-TARGET`
- `Nexa-API-FulfillmentDelivery-TARGET`
- `Nexa-API-CreditPaymentDocuments-TARGET`
- `Nexa-API-IntegrationReliability-ASIS`
- `Nexa-Platform-Frontend-TARGET`
- `Nexa-Portal-Frontend-TARGET`

Validate the DSL with the pinned local image from `tooling/structurizr/compose.yml` or the equivalent read-only command:

```bash
docker run --rm \
  -v "$PWD/03-system/c4/structurizr:/usr/local/structurizr:ro" \
  structurizr/structurizr:2026.06.28 validate \
  -workspace /usr/local/structurizr/workspace.dsl
```

The expected system-context, container and component views, zero deployment views and DSL-to-generated semantic equivalence are checked by `tooling/scripts/validate-blueprint.sh`. The validator exports a temporary JSON from DSL, then compares semantic content while ignoring generated IDs, timestamps and layout. `workspace.json` is retained as generated output and must be regenerated by Structurizr, never hand-edited.

To refresh generated JSON while preserving intentional layout, export JSON from `workspace.dsl`, then run Structurizr `merge` with the committed workspace as `-layout`. The validator does not accept stale relationship descriptions, names, technologies, tags or view membership.
