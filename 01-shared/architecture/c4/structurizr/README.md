# C4 Structurizr

Reviewed tool version: `structurizr/structurizr:2026.06.28`.

`workspace.dsl` plus included DSL files are the canonical semantic C4 source.
`generated/workspace.json` is generated output; never edit it by hand.

The source uses modular `!include` composition: `model/` owns people, systems,
containers, component scope, relationships and deployment environments; `l1/`,
`l2/`, `l3/` and `deployment/` own direct views. AS-IS views exclude the planned
Mobile containers. V1 TARGET views include the two planned Mobile apps and
provider-neutral external systems. L4 code views live outside Structurizr and
use Mermaid or repository evidence.

The V1 system-context question is **who uses Nexa and which external systems does it depend on?** The V1 container question is **which major runnable applications and data stores make up Nexa?** Local Docker services are not added merely because Compose declares them; see the [canonical C4 rationale](../README.md) and [runtime evidence](../../../../04-delivery/as-is/compose-runtime-architecture-evidence.md).

Run Structurizr Local from this directory:

```bash
cd 01-shared/architecture/c4/structurizr
docker compose up
```

Open `http://localhost:9090`.

Validate the DSL with the pinned local image:

```bash
docker run --rm \
  -v "$PWD:/usr/local/structurizr:ro" \
  structurizr/structurizr:2026.06.28 validate \
  -workspace /usr/local/structurizr/workspace.dsl
```

The expected system-context, container, component and deployment views and
DSL-to-generated semantic equivalence are checked by
`tooling/scripts/validate-blueprint.sh`. The validator exports a temporary JSON
from DSL, then compares semantic content while ignoring generated IDs,
timestamps and layout. `generated/workspace.json` is retained as generated
output and must be regenerated by Structurizr, never hand-edited.

To refresh generated JSON while preserving intentional layout, export JSON from `workspace.dsl`, then run Structurizr `merge` with the committed workspace as `-layout`. The validator does not accept stale relationship descriptions, names, technologies, tags or view membership.
