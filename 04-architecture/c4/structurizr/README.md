# C4 Structurizr

`workspace.dsl` is the canonical semantic C4 source. `workspace.json`, if generated by Structurizr through layout editing, is a generated/compiled representation including layout and is not hand-written.

The source uses modular `!include` composition. V1 views exclude future people, future containers and future external systems. Runway views include planned Mobile, Driver, V2, identity-provider and IoT/telemetry elements with explicit future tags. C4 L3, component views and deployment views are not created.

The V1 system-context question is **who uses Nexa and which external systems does it depend on?** The V1 container question is **which major runnable applications and data stores make up Nexa?** Local Docker services are not added merely because Compose declares them; see the [canonical C4 rationale](../README.md) and [runtime evidence](../../../08-operations/containers/compose-runtime-architecture-evidence.md).

Expected views:

- `Nexa-SystemContext-V1`
- `Nexa-Containers-V1`
- `Nexa-SystemContext-Runway`
- `Nexa-Containers-Runway`

Validate the DSL with the bundled local image from `tooling/structurizr/compose.yml` or the equivalent read-only command:

```bash
docker run --rm \
  -v "$PWD/04-architecture/c4/structurizr:/usr/local/structurizr" \
  structurizr/structurizr:latest validate \
  -w /usr/local/structurizr/workspace.dsl
```
